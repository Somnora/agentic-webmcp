Privacy for the public demo

Effective August 25, 2026

Agentic WebMCP is a stateless demonstration. It does not create user accounts, set cookies, request payment information, or store origin selections, searches, taste and intent, recommendations, activity itineraries, purchase reviews, approved selections, or generated briefs in an application database.

Infrastructure data

Cloudflare hosts the application and may process standard request, URL, security, log, and trace metadata needed to deliver, monitor, and protect the service. Application records contain a random request correlation id, route path, response status, duration, adapter timing, response byte count, normalized failure category, stable error code, and retryability. They do not contain search terms, taste and intent fields, request bodies, upstream response bodies, tokens, or cookies. Taste and intent use a no-store request and are never placed in the request URL. There are no third-party analytics identifiers. Do not enter personal or confidential information into the public demo.

Offer data

The Worker reads only exact HTTPS hostnames and product or service paths declared in its validated origin manifests. Runtime access stops at each origin's authorization review date, before another upstream request is made. The default origin is agentic-webmcp-origin.somnora.workers.dev, a first-party controlled public marketplace with original guitar listings and no external product images. A separate `/services/*` scope on that controlled hostname contains seven original local-service and destination-activity fixtures, including five Oahu experiences. Its JSON and HTML responses are fetched live and clearly labeled as controlled demonstration data. The secondary Shopify development store can use a read-only Storefront token, public products JSON, or a clearly labeled research-only bundled snapshot. Fallback and stale Offers cannot create a purchase review. Search terms do not include an Agentic visitor identity.

Agent tools

Ten WebMCP tools read origins, Offers, ranked recommendations, stripped page content, and planning-only activity itineraries. A recommendation may ask one refinement question when eligible options have competing evidence. The answer remains in page-local state and the no-store request only long enough to rerank and optionally create the dossier. create_activity_itinerary uses the submitted date, party size, budget, pace, and day hours to propose a source-linked schedule. It does not reserve a service, confirm live availability, measure travel time, contact a provider, or pay. propose_add_to_cart stages a goods purchase review but does not create an order. Only the human approval button can create an in-page decision record after the Worker confirms the reviewed Quote still matches current facts. No tool exposes booking, provider messaging, checkout, payment, account, order, customer, billing, or merchant mutation capability. Tool activity disappears when the page is closed or reloaded.

Decision dossier

The Download dossier button creates a Markdown file in the browser from the visible research activity, taste and intent, refinement question and answer, source URLs, evidence state, selection, and human decision. The dossier is downloaded directly to the visitor's device. It is not uploaded to or stored by Agentic.
